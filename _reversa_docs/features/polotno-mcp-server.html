Visão Geral

O **Polotno MCP Server** é um servidor nativo baseado no protocolo aberto **Model Context Protocol (MCP)**, embutido no Polotno Studio para permitir que agentes de IA inspecionem, criem e alterem designs visuais programaticamente em tempo real via chamadas de ferramentas RPC.

---

Responsabilidades

  • Expor catálogo semântico de ferramentas para agentes de IA compatíveis com MCP.
  • Validação estrutural de payloads de design com Zod e `@polotno/schema`.
  • Aplicação de patches atômicos em designs abertos utilizando JSON Patch (RFC 6902).
  • Renderização sob demanda de páginas do canvas em imagens para alimentar modelos com visão.
  • Inspeção algorítmica de qualidade e lint visual de layouts.
  • Suporte a transporte duplo: STDIO/SSE padrão do MCP e bridge HTTP Express local.

---

Regras de Negócio

  • **RN-PMS-01**: Toda mutação estrutural em lote de um design deve ser validada contra `@polotno/schema` antes de ser despachada para o canvas. 🟢 CONFIRMADO
  • **RN-PMS-02**: Os findings de lint reportados pela ferramenta `lint_design` carregam severidade `error` ou `warning`, mas nunca bloqueiam forçadamente edições do agente. 🟢 CONFIRMADO
  • **RN-PMS-03**: Os aliases canônicos (`render`, `export`, `lint`, `save`) devem ser resolvidos de forma idêntica tanto em chamadas MCP quanto em requisições HTTP REST. 🟢 CONFIRMADO

Arquitetura de Transporte Duplo

O servidor MCP suporta dois modos de operação simultâneos:

1. **Transporte Padrão MCP (STDIO / SSE)**:

  • Utilizado por assistentes e IDEs de IA (Claude Desktop, Cursor, Antigravity).
  • Registrado via `McpServer` do `@modelcontextprotocol/sdk`.

    • 2. **Transporte HTTP Express (`index.ts`)**:

  • Expõe endpoints REST na porta local interna para ferramentas ou scripts que preferem HTTP convencional:
  • `POST /tool/:verb` (executa a ferramenta correspondente).

---

Registro e Despacho de Ferramentas (`ToolDef`)

Cada ferramenta é definida por uma estrutura neutra em `tools.ts`:

```typescript

export interface ToolDef {

name: string;

description: string;

schema: Record<string, z.ZodType>;

handler: (args: any) => Promise<ToolResult>;

}

```

O despachante executa `rpc('design.exec', { docId: designId, command })` enviando a instrução serializada para o processo de renderização do Electron, aguarda a execução na prancheta e desembrulha o resultado com controle de revisão incremental (`rev`).

---

Riscos e Lacunas

  • 🟡 **INFERIDO**: Múltiplos agentes conectando-se simultaneamente ao mesmo `designId` podem gerar conflitos de revisão caso tentem aplicar JSON patches concorrentes (race conditions em `rev`).
