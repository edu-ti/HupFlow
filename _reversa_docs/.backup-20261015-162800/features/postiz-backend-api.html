Visão Geral

O **Postiz Backend API** é o núcleo de serviços da plataforma de gerenciamento social, construído sobre NestJS 11, Prisma ORM e PostgreSQL, responsável por autenticação, isolamento multi-tenant, persistência de posts e mídias, faturamento Stripe e despacho de jobs para o orquestrador Temporal.

---

Responsabilidades

  • Autenticação e emissão de tokens de sessão JWT e OAuth social.
  • Controle de acesso baseado em papéis (RBAC) e isolamento multi-tenant por Organização.
  • Gestão do ciclo de vida editorial de postagens (rascunhos, agendamento, publicação imediata).
  • Gerenciamento de credenciais e contas de redes sociais conectadas.
  • Upload de arquivos de mídia (integração local, AWS S3 e Cloudflare R2).
  • Integração de pagamentos, assinaturas e webhooks com Stripe.
  • Exposição da API Pública (`/v1`) autenticada por chaves de API (`X-API-KEY`).

---

Regras de Negócio

  • **RN-PBA-01**: Nenhuma consulta ou mutação de dados pode ser executada sem filtrar explicitamente pelo `organizationId` validado no token JWT ou na API Key. 🟢 CONFIRMADO
  • **RN-PBA-02**: Posts agendados com data futura devem disparar a criação de workflows idempotentes no Temporal com o ID do post como identificador único. 🟢 CONFIRMADO
  • **RN-PBA-03**: Organizações com pagamentos em atraso (`PAST_DUE`) ou canceladas têm funcionalidades de agendamento bloqueadas. 🟢 CONFIRMADO
  • **RN-PBA-04**: O upload de arquivos de mídia deve validar o tamanho máximo e os MIME types aceitos antes de persistir em disco ou nuvem. 🟢 CONFIRMADO

Arquitetura de Módulos NestJS

  • `AppModule`: Módulo raiz que importa os submódulos de infraestrutura e rotas de domínio.
  • `ApiModule`: Agrupa os 31 controladores REST e seus provedores de serviço associados.
  • `DatabaseModule`: Provê a instância singleton do `PrismaService` conectado ao PostgreSQL.
  • `ThrottlerStorageRedisService`: Provê o backend de persistência em memória do Redis para contadores de taxa.
  • `TemporalModule`: Cliente gRPC do Temporal Server para disparo de workflows assíncronos.

---

Estratégia de Autenticação e Guards

1. **JWT Auth Guard**:

  • Extrai o cabeçalho `Authorization: Bearer <token>` ou cookies de sessão.
  • Decodifica a sessão e obtém o `userId` e o `activeOrganizationId`.

    • 2. **API Key Guard**:

  • Aplicado na rota `/v1/*` (`PublicController`).
  • Valida o cabeçalho `X-API-KEY` contra a coluna indexada `Organization.apiKey`.

    • 3. **CASL Ability Guard**:

  • Avalia permissões granulares de acordo com o papel (`ADMIN`, `USER`, `VIEWER`).

---

Riscos e Lacunas

  • 🔴 **LACUNA**: Ausência de suíte de testes de integração (Supertest) para cobrir os fluxos de autenticação e validação de webhook do Stripe.
